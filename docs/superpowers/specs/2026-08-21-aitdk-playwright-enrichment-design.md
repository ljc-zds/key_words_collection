# AITDK Playwright Enrichment Design

## Objective

Validate that the installed AITDK SEO Extension can be used through its normal
browser flow from a dedicated Playwright browser profile. The validation must
collect traffic and keyword data for one domain without extracting or replaying
the extension's signing secret.

## Scope

This first delivery covers only the browser enrichment adapter and a one-domain
smoke test. Product Hunt collection, demand filtering, scheduling, and Obsidian
report generation will be added only after this adapter has a repeatable result.

## Architecture

The extension archive is unpacked into a project-local ignored runtime folder.
Playwright launches a persistent Chromium-compatible context with:

- a dedicated user-data directory, separate from the user's Edge profile;
- the unpacked AITDK extension supplied through Chromium extension launch flags;
- a browser executable selected from locally installed Edge or Chromium;
- an explicit single-domain task input.

The adapter navigates to the target domain, waits for the AITDK UI/content
script to complete its ordinary query, and observes results generated by that
flow. It parses only structured data exposed by the extension-rendered state or
the extension's own browser event stream. It does not derive, store, emit, or
reuse the extension's signing secret, cookies, nonce, signature, or complete
signed URLs.

## Data Contract

The smoke test produces one JSON record with the following optional fields:

- domain, title, description;
- Whois creation date/domain age if the plugin exposes it;
- monthly visits, search-organic share, and direct share;
- top keywords, regions, and traffic-source data;
- collection timestamp and a structured failure reason when collection fails.

Raw browser responses are not persisted by default. Sanitized diagnostic logs
must redact query-string credentials and request headers.

## Failure Handling

The smoke test fails clearly when the extension cannot load, its UI cannot be
found, the plugin is not authenticated, a query times out, or expected traffic
data is absent. It stores no partial credentials. A failure should leave the
dedicated profile available for manual inspection, but never alter the user's
existing Edge profile.

## Testing And Acceptance

Tests are written before the production adapter. Unit tests cover archive
layout validation, result parsing, and diagnostic redaction. A gated manual
integration smoke test uses `deno.com` and is considered successful only when
it emits a sanitized record containing the domain plus at least one plugin data
section (traffic or Whois). It must run without manually copying requests from
DevTools.

## Follow-Up Delivery

Once the smoke test is repeatable, the next spec will add Product Hunt product
collection, website normalization/deduplication, traffic thresholds, brand-term
exclusion, and Markdown report writing under the Obsidian vault.
