# 关键词建站分析报告 HTML 设计方案

## 1. 产品定位

HTML 不是关键词明细表，也不是 Excel 的复制版，而是面向建站决策的分析报告。它回答三个问题：

1. 哪些主题值得做？
2. 为什么值得做？
3. 具体应该做什么网站、如何验证和变现？

Excel 保存逐关键词的可审计数据；HTML 只输出聚合统计、主题判断、项目建议和行动计划。报告必须同时帮助判断关键词质量和建站优先级，不能只描述主题规模。

## 2. 页面总体结构

页面采用单页报告结构，顶部提供目录锚点。章节顺序固定为：

1. 报告概览
2. 执行结论
3. 数据来源分析
4. 关键词机会结构
5. 主题聚类分析
6. 主题建站方案
7. 优先级建议
8. 变现机会分析
9. 风险与限制
10. 下一步执行计划

不输出完整关键词列表。最多展示每个主题 1–3 个代表性项目，用于说明方向。

## 3. 报告概览

顶部使用数字卡片展示：

- 分析日期和数据更新时间
- 原始候选记录数
- 最终保留记录数
- Similarweb 记录数
- Semrush 记录数
- 推荐优先建站数量
- 覆盖市场（US、Global 等）

同时显示筛选口径：搜索量 `>= 5,000`、CPC `>= 0.01`、KD 分档上限 `30/45/60`，以及敏感、品牌和版权风险排除规则。

## 4. 执行结论

结论必须基于当前数据动态生成，至少包含：

- 词量最多的三个主题
- 平均搜索量最高的主题
- 平均 KD 最低的主题
- 平均 CPC 最高的主题
- 最适合快速做 MVP 的主题
- 最适合广告、订阅和付费资源的主题
- 高风险或暂缓主题

结论写成中文段落，不只显示百分比。例如：

> 计算器主题的用户动作明确，单页即可交付计算结果，适合先制作 MVP；内容资料主题流量较大但商业意图较弱，更适合广告和专题集群。

## 5. 数据来源分析

使用真实数据生成来源图表和说明：

- Similarweb 总数
- Semrush 总数
- 两来源重合数
- 仅 Similarweb 数量
- 仅 Semrush 数量

如果数据中没有可靠的重合标识，必须明确显示“重合数未计算”，不能估算。旁边说明：Similarweb 主要用于发现和扩展，Semrush 主要用于搜索量、KD、CPC 验证；两个平台口径不可直接相加。

## 6. 关键词机会结构

生成六个真实分布模块，使用横向条形图或简单柱状图，避免依赖外部图表库：

1. 来源分布
2. 推荐站点类型分布
3. 高、中、低优先级分布
4. 搜索量区间：`5,000–9,999`、`10,000–29,999`、`30,000–99,999`、`100,000+`
5. KD 区间：`0–30`、`31–45`、`46–60`
6. CPC 区间：`0.01–0.49`、`0.50–0.99`、`1.00–2.99`、`3.00+`

每张图下方必须有一句解释，说明该分布对建站优先级的影响。

## 7. 主题聚类分析

按关键词模式和已有站点类型聚类，默认主题为：

- 计算器和分析工具
- 游戏辅助和数据工具
- 图片、音频、视频处理
- 字体、模板和素材
- 内容解释和资料查询
- 其他可产品化需求

每个主题输出真实统计表：

| 字段 | 说明 |
|---|---|
| 关键词数量 | 该主题的去重关键词数 |
| 总搜索量 | 主题内搜索量合计，仅作规模参考 |
| 平均搜索量 | 主题平均月搜索量 |
| 平均 KD | 主题平均竞争度 |
| 平均 CPC | 主题平均商业价值信号 |
| 代表项目 | 搜索量最高或综合评分最高的 1 个词 |
| 开发复杂度 | 低、中或高 |
| 推荐变现 | 与主题匹配的标准变现类型 |

## 8. 主题建站方案

每个主题必须写清楚以下 9 项，而不是只写一句方向描述：

- 用户在搜索什么
- 用户要完成的具体任务
- 推荐网站或页面类型
- MVP 功能清单
- 后续扩展功能
- 推荐变现方式
- 开发复杂度
- SEO 扩展方式
- 主要风险

示例：交易计算器应描述为“选择交易对象、输入双方数据、计算价值差、输出公平度评分、生成分享链接”，而不是笼统写“做一个工具站”。

## 9. 优先级建议

### 两套评分

报告必须区分两个分数：

- **关键词质量分**：由搜索量、KD、CPC、搜索意图、数据完整度、SERP 机会信号和品牌/版权/敏感风险共同计算，用于判断关键词本身是否值得保留。
- **建站优先级分**：由关键词质量、单页承接能力、MVP 开发复杂度、变现清晰度、数据维护成本、域名风险和 SERP 竞争共同计算，用于安排开发顺序。

两者不能混用。高流量品牌词可能质量高，但因商标风险，建站优先级仍应为“暂缓”。

分成三档，并说明判定依据：

### 优先验证

搜索量较高、KD 较低、CPC 存在、用户动作明确、单页可以交付结果，并且存在广告、订阅、联盟或付费功能空间。

### 次优先验证

需要内容积累、模板授权、数据维护或功能差异化，但仍然有明确用户需求和变现可能。

### 暂缓

品牌导航、成人和敏感内容、版权下载、搜索意图不稳定、SERP 被强品牌完全占据，或没有清晰变现路径的方向。

HTML 只展示主题和少量代表项目，不展示完整关键词清单。

### 代表项目卡片

每个主题展示 3–5 个建站优先级最高、搜索量最高或 KD 最低的代表项目。每张卡片包含关键词、搜索量、KD、CPC、质量分、建站优先级、搜索意图、推荐页面、MVP、变现方式、风险和保留/暂缓原因。完整明细仍只放在 Excel。

### 淘汰原因统计

报告按数量和占比统计淘汰或暂缓原因：品牌/导航、成人或敏感、版权/下载、SERP 强品牌、意图不明确、搜索量/KD/CPC 不合格、无页面承接、无变现路径、开发或维护成本过高。无法归因的记录标记为“未分类”，不得静默丢失。

## 10. 变现机会分析

统一使用以下枚举：

- 广告
- 订阅
- 一次性付费
- 联盟佣金
- 游戏内广告
- 赞助
- 付费资源
- 线索获客

报告应统计各主题适合的变现方式数量，并给出匹配说明：工具适合订阅和付费导出，游戏适合广告、会员和赞助，素材适合付费资源和联盟，内容适合广告和赞助，B2B 需求适合订阅和线索获客。

有明确付费路径的关键词获得优先级加分；只有泛流量广告、用户动作弱的词只能作为内容项目评估，不能因为搜索量大就自动优先建站。

## 11. 风险与限制

必须明确说明：

- Similarweb 与 Semrush 的数据口径不同
- 搜索量不能简单相加
- KD 只是竞争度参考
- CPC 不等于实际收入
- 必须人工复核 Google SERP
- 品牌词有商标风险
- 下载器、字体和图片素材可能有版权风险
- 游戏数据可能受数据源和平台政策影响
- AI 判断只能辅助，不能替代市场验证
- “适合建站”不代表保证流量或收入

## 12. 下一步执行计划

按执行顺序展示：

1. 从优先主题选择 5–10 个代表项目。
2. 查看 Google SERP，确认弱站、论坛、内页和内容空缺。
3. 检查域名可用性、品牌和版权风险。
4. 确定页面类型和 MVP 功能范围。
5. 先上线 1–2 个 MVP。
6. 接入分析、广告和转化追踪。
7. 根据访问、留存、点击和收入决定是否扩展页面集群。

## 13. 生成规则

### 模型分工与成本控制

- Excel 中逐关键词的“关键词是干嘛的”属于批量解释任务，使用当前可用的最低成本模型，按 10–20 条一批生成；只要求输出用户搜索目的、期望结果、适合页面和主要风险，不调用主模型。
- HTML 报告的主题聚类、质量判断、建站优先级、变现分析和结论由主模型负责，输入为已经结构化的统计数据和代表项目，避免把全部关键词原文重复发送给模型。
- 能通过规则、SQL 或 Python 计算的数量、均值、分布和排名，不消耗模型 token；模型只处理语义判断和报告文字。
- Excel 解释失败时使用规则模板降级，并标记“规则生成”；HTML 报告失败时不得覆盖上一版，输出带日期的新文件。
- 批量解释结果需要按关键词去重缓存，已经生成过且关键词数据未变化的记录不重复调用模型。

- 每次从最新 `site_keywords.json` 重新计算，不在旧 HTML 上追加文本。
- 输出新文件名，例如 `keyword_site_analysis_final_YYYYMMDD.html`。
- 使用 HTML 内嵌 CSS，离线打开可用，不依赖外部 CDN。
- 所有数字保留千位分隔；百分比保留 1 位小数；KD 和 CPC 按实际精度展示。
- 数据为空时显示“暂无数据”，不得填入伪造的 0 或通用结论。
- HTML 不包含 Excel 的逐词明细；Excel 作为审计和执行清单单独交付。
- 生成后检查章节是否齐全、图表是否有数据、是否误包含完整关键词表。
- 检查每个代表项目都有质量分、建站优先级、页面类型、MVP、变现和风险说明。
- 检查淘汰原因数量与原始候选数、保留数可对账；无法归因的记录必须显示为“未分类”。
